# Image Generation (tool + console panel + Telegram photo)

Status: shipped in car 4c (`mycore/imagegen.py`; tool wiring in
`mycore/tools.py`, panel endpoint in `web/server.py`, TG delivery in
`mycore/service.py`). Companion pages: [capabilities.md](capabilities.md)
(the `media.image` block), [voice_session.md](voice_session.md).

Image generation is **BYOK against an OpenAI-compatible
`/v1/images/generations` endpoint** — no paid dependency ships with the
product, and an unconfigured install fails honestly at every surface instead
of pretending.

## 1. Three surfaces, one engine

| Surface | Entry | Behavior |
|---|---|---|
| Agent tool | `generate_image {prompt, size?}` | **Always registered** — configuration resolves at *call* time, so an unconfigured endpoint surfaces as an honest `ERROR:` line (never a missing capability, never a raise); success renders one `saved: <path>` line per image |
| Console panel | `POST /api/image` (Bearer `WEB_TOKEN`) → `GET /api/media/<name>` | Chat view IMAGE TRIAL card: prompt → thumbnail grid; unconfigured → 503 `{error: <reason>}` shown verbatim under the badge |
| Telegram | `generate_image` during a turn → outbox → `sendPhoto` | text reply first, photos after (§3) |

Tool arguments: `prompt` (non-empty), `size` (`WxH`, default `1024x1024`).
Panel caps: prompt 1–2000 chars, `size` must match `WxH` (400 otherwise).

## 2. Configuration chain

Endpoint base URL — first non-empty wins:

1. env `AIDOG_IMAGE_URL`
2. settings `media.image_base_url`
3. settings `mycore.base_url` (the kernel endpoint — out of the box, a
   configured gateway *is* the image endpoint)

Credential — `IMAGE_API_KEY` falling back to `MODEL_API_KEY` (own-line
reader: process env first, then `<repo>/secrets.env`). **The value never
reaches a log, an error message, a repr or a return value.**

- A **loopback** endpoint may run keyless (local gateway convention —
  requests still carry `Authorization: Bearer local`);
- a **remote** endpoint without any slot → `configured() == (False, "…slot
  not set")` — fail-closed, slot NAMES only.

`media.image_model` (settings, ≤64 chars) is optional: empty → the `model`
field is omitted and the gateway infers; set → sent in the payload.
Settings validation: `media.image_base_url` must be an http(s) URL with a
host (empty = off).

## 3. Outbox semantics (process-level, text never sacrificed)

`generate()` appends `(path, prompt)` to a **module-level outbox** guarded
by a lock; `drain_outbox()` takes everything atomically (idempotent — a
second drain is empty).

- **Web process**: the panel endpoint drains its own copy immediately after
  generating — panel images are console-local previews and must never
  accumulate in a process that has no Telegram sender.
- **Service process**: after a turn's **text reply is delivered**, the
  service drains its copy and sends each photo via `sendPhoto`
  (multipart; caption = prompt, hard-cut at 1000 chars — Telegram's cap is
  1024). A photo failure only logs `SEND_PHOTO_FAIL` — it can never touch
  the delivered text. `--dry-run` logs `DRYRUN_SEND_PHOTO` and transmits
  nothing; success logs `SEND_PHOTO_OK`.

Because the outbox is per-process, an image generated by the console never
leaks into a TG chat and vice versa — each side drains only what it created.

## 4. Storage and serving

- Files land in `data/images/<sha256>.png` (content-addressed — identical
  bytes dedupe to one file; `data/` is gitignored).
- `GET /api/media/<name>` serves **one generated image and nothing else**:
  the name must match `[A-Za-z0-9_.-]{1,128}`, must resolve to a file
  *directly inside* `data/images/` (resolved-parent check kills
  `..`/encoded traversal), and must carry a known image suffix
  (`.png/.jpg/.webp`) — anything else is a plain 404. Read-only, no auth
  (same loopback posture as `GET /api/status`).
- **Gallery (0.5.51, X17)**: `GET /api/artifacts?limit=&offset=` lists the
  same directory as metadata rows (`{name, url, size, when, ext}`, limit
  1..200, `truncated` flag) and the Stream view renders thumbnails that
  link back to `GET /api/media/<name>` — names are whitelisted the same
  way, an empty directory is an honest empty 200, and a read failure is a
  503. It is a **read-only index of what already exists**, not a second
  storage path.

## 5. Honest boundaries

- **Unconfigured = honest failure everywhere**: tool → `ERROR: image
  generation not configured: …`; panel → 503 with the real reason;
  `GET /api/capabilities` → `media.image.configured: false` plus a
  URL-stripped `reason`. No placeholder art, ever.
- **Upstream errors are bounded and key-free**: HTTP status + up to 160
  chars of upstream body, credential value never included; a 500-response
  body truncated to that bound. Invalid JSON / empty `data[]` → honest
  `ImageError`.
- **Response formats**: prefers `response_format: "b64_json"`; tolerates a
  `url` reply (downloads it with a plain GET). `n` is clamped to 1..10.
- **Pending credentials**: end-to-end reachability to a real image provider
  is BYOK — verified here against a local mock endpoint; real-provider
  connectivity is pending the operator's own endpoint/key.

## 6. Verification (what actually exercises this)

- **Core suite** (`mycore/tests/run.py::test_imagegen`): config precedence
  (env > `media.image_base_url` > `mycore.base_url`, slash stripping), the
  four `configured()` states (remote w/o key rejected, key unlocks, loopback
  keyless), argument validation, b64 happy path writing a real PNG +
  outbox queue/drain idempotence, payload shape, upstream 404/500 → bounded
  `ImageError` with the sentinel key absent, and the `url`-reply download
  leg — all against a loopback mock, zero network, zero real keys.
  `test_media_tools` covers the registry contract (always-registered tool,
  honest ERROR lines, `saved:` rendering) and `test_service_media` covers
  text-first/photo-after ordering incl. dry-run.
- **Web smoke** (`tests/web_console_p3.py`): `GET /api/media` whitelist
  (unknown name / encoded traversal / wrong suffix → 404), the `media`
  settings partition (illegal `image_base_url` → 400 + exact reason,
  byte-identical settings), and `media.image` in the zero-credential
  capability assertion.
- **E2E** (`tmp/e2e_car4c.py`): settings `media.image_base_url` pointed at a
  local mock `/images/generations` (settings snapshotted, console
  restarted) → real `POST /api/image` → `200` with a sha256-named record →
  `GET /api/media/<name>` returns PNG magic; byte-for-byte restore + smoke
  re-run at the end.
- **Console coverage (frontend car, 0.5.39)**: `IMAGE_API_KEY` joins the
  `media` group of the Settings credential editor, so the BYOK fallback
  chain (`IMAGE_API_KEY` → `MODEL_API_KEY`) is now visible as presence —
  both slots are listed, neither value ever serializes. Evidence:
  `tmp/e2e_frontend_coverage.py` `L1` (slot catalog, set/clear roundtrip,
  sentinel sweep) and `tmp/e2e_frontend_ui.js` `U2` (editor + DOM scan) —
  see [frontend_coverage.md](frontend_coverage.md).
