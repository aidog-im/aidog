Get Started

From zero to a running console in three steps. What you need first: Linux, or Windows through WSL2, with Python 3.10+, tmux and git — plus two things only you can bring: a model endpoint and a Telegram bot token.

1

Get the repository

I'm AiDog is public on GitHub — clone it with zero credentials.

git clone https://github.com/AiDog-im/AiDog.git aidog && cd aidog
▸
2

Run the installer

One command: provision + boot + verify. The installer is idempotent, so re-running it is always safe.

bash deploy/install.sh
▸
3

Fill the slots

The wizard asks for what only you have: a console token (any long random string you invent), your bot token, who may talk to it, and where your model lives. A model key is optional — a local endpoint needs none. Values are hidden as you type and never echoed; the console's ACTIVATION card mirrors the same check, with a FIX deep-link on every failing row.

aidog setup

Then open http://127.0.0.1:8790 — the console is already running.

Full install guide — prerequisites, every slot, troubleshooting

Everything here is public today — clone the repository and run the installer. No waitlist, no sign-up key: releases are on GitHub.

03

Capabilities

What the product actually does, card by card — every line comes from the release gates and the capability docs, thirty-six of them in the repository today, nothing invented.

Streaming chat everywhere

Console chat streams by SSE and Telegram replies stream behind a typing heartbeat, so an answer reaches you as it is written.

Voice sessions & media BYOK

Local speech-to-text sessions with fuzzy wake phrases, TTS announcements through your own engine key, BYOK image generation and Telegram photo send.

Skill workshop

Skills ship as SKILL.md with industry-standard frontmatter; the deterministic router picks the TOP3 candidates before any body loads — 30/30.

Two-layer memory

Curated long-term memory in bounded Markdown budgets with archive tiers, plus a user-profile layer — memory suite 58/58, no vector store you cannot read.

Natural-language cron & self-evolution

Schedule in plain language — /cron ship the report tomorrow 9am parses into a job that stays fail-closed until you enable it — while /learn and /reflect grow the loop behind lint-gated writes. Automatic evolution ships off; you switch it on.

9-route channel gateway

Telegram is live; nine adapters — Discord / Slack / Email / Webhook / DingTalk / Feishu / WeChat / WhatsApp / Signal — each reports an honest status and stays silent while unconfigured.

Desktop HUD shell

An Electron frameless shell with transparency slider, always-on-top and tray — Linux packaging verified, Win/macOS honestly not built yet; desktop suite 15/15.

Multi-profile isolation

AIDOG_PROFILE selects fully isolated profiles — settings, secrets, state and body kept apart — proven by a 63/63 isolation gate and an 18-leg real-machine E2E.

Terminal backends & code runs

The shell backend is grammar-checked local, Docker or SSH; execute_code folds into at most 8 steps with checkpointed file writes you can restore.

Subagents & MCP

Up to three isolated parallel delegates with fresh context, plus an MCP client for stdio and HTTP servers with tool allow/deny filtering.

Hooks & context files

Seven lifecycle events can run your own command on a timeout — the child gets only PATH and HOME, never a credential — and context dirs pull shared files into a turn.

OpenAI-compatible gateway

The loopback console exposes GET /v1/models and POST /v1/chat/completions — streaming and non-streaming — behind a Bearer token for OpenAI-style tooling.

Doesn't stop at the first failure

Multi-upstream failover with per-endpoint tests and rate caps, web fetch that can route through a relay you run yourself, and a model tier that moves on when an endpoint goes quiet — a dead endpoint costs a retry, not the night.

Runs while you sleep

Plain-language cron, missions with milestones and red lines, and a watchdog that keeps a 24/7 escalation journal — reaching you on Telegram once you give it a chat id. The schedule reads as a rhythm: every job shows its next-due time.

Always under your hand

A tail you can read — IDLE, WORKING, PAUSED, BUDGET HOLD — plus STOP and PAUSE on the Overview, daily budget guardrails, and rules and forbidden zones the constitution has to honour.

It keeps a memory of you

Beyond the tasks it keeps a profile of you — what you prefer, what you said matters — written and updated by the model itself and shown as a gauge in the console. A browsable view of it is next.

Extensions — one panel, three tabs

The console's Extensions panel opens three doors: keyless market quotes, your smart home, and your vehicle — the last two are thin paths into Sniff, observed read-only and never driven.

04

Sniff — the nose that speaks first

A read-only sweep smells health, home, vehicle and web signals, turns them into findings with provenance, and speaks first only when one earns it.

Sniffing the room — the part of a dog that notices before you do.

◎

1 · Senses

A sweep reads only what it may read: Home Assistant states behind a bearer slot, one web page, or a declared bridge's configuration and session status. Never-configured stays silent; a source we did not reach is never called reachable.

▸
◇

2 · Sweeps

Bounded rules — no eval, a closed operator set, a sustain window — evaluate the readings the sweep just produced. A match becomes a durable, deduplicated finding in a local log your machine owns.

▸
◉

3 · Speaks first

Quiet hours, a digest cap, the global PAUSE and a per-rule speak flag decide whether a batch earns a message — delivered oldest-first through the same chain the cron lane uses.

home — Home Assistant

Entity states filtered by globs, the hub route for health sensors, locks and devices — GET only, never a service call.

web — one URL

A page hash plus an optional regex field, so a changed page or a crossed threshold becomes a reading instead of a guess.

mcp — borrowed bridges

Configuration and connection status of a bridge you run yourself — observed, never driven: no tool call, no spawned process, no connection of its own.

Use it in three steps

After install, open the Console → SENSE: add a source (a Home Assistant url + token slot, a URL + extract regex, or a bridge name from mycore.mcp), then add a rule like sensor.temp > 30 for 10m.

Hit SWEEP NOW (or wait out the interval): hits land in the FINDINGS timeline and stay on your machine — rules marked speak reach you first, with quiet hours, the digest cap and PAUSE deciding when.

Read-only by construction — no actuation path exists in the engine at all, and the suite asserts that absence. Personal signals stay on your machine, unconfigured sources never speak, and no paid tier ever touches them.

07

Security & Trust

Local-first by construction — the quiet guarantees, stated plainly.

Loopback by default

Services listen on 127.0.0.1 only — reachable from your machine, not from your network.

Credentials stay local

Secrets live in one gitignored file (mode 0600). Output and logs report slot names and lengths — never values.

Writes need your token

Every console write operation requires your local access token.

Telemetry off by default

Usage tallies on your machine. Nothing leaves it unless you opt in.

en + zh interface, English source

The interface speaks English and Chinese; all source code is written in English.

Free forever

Permanently free — no paid tier, no in-app purchase, no usage fee, ever.

One passphrase, one file

Backup & Restore encrypts your credentials, settings and memory into a single .ckx file inside your browser — the passphrase never reaches the server. You can also schedule agent backups that re-run it on a timer you set, with a local call meter and a round-trip restore check.

It can be told off, and it keeps the correction

Rules and forbidden zones sit directly under the constitution. On any conflict the constitution wins, and the reply has to say which rule it did not apply.
